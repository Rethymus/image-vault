# Troubleshooting and lessons learned

## “My private GitHub repository is private, so why can people see the Pages site?”

GitHub source visibility and Pages output visibility are separate. Do not publish a management page to Pages and assume the private source repository protects it. Put the management surface behind Access or keep it out of the public artifact.

## “I cannot find Domains & Routes in Cloudflare Access”

For a `workers.dev` deployment, the relevant Access destination can be the Worker itself. In the current Cloudflare One UI, create a Self-hosted application and choose the Worker destination. A custom domain is optional for this personal setup.

## “The phone gets an Access login after scanning”

The phone upload Worker was probably placed behind the owner-only Access application. Remove it from that application. Only `vault-admin` needs Access; `vault-upload` must remain public and validate the random session token itself.

## “The public upload Worker root is blank or 404”

That is intentional. The root and admin-style API paths do not expose an application. A valid path has the shape `/s/<43-character-token>` and is generated by the admin UI.

## “The QR closed, but the uploaded image still opens”

That is expected. QR revocation stops further uploads; it does not delete image objects or revoke already issued public image URLs. Delete or rotate the asset in the owner manager when necessary.

## “The image list does not update immediately”

The admin UI polls while the QR sheet is open. Keep the sheet open for a few seconds after the phone upload. If it still does not update, inspect `/api/assets` with an authenticated browser and check the Worker logs.

## “The Worker deploys but the UI stays in demo mode”

The UI defaults to demo mode unless `VITE_API_MODE=worker` is present in the production build environment. Check `.env.production` locally or the environment variables in the GitHub Actions build step. Never put a secret in a `VITE_*` variable.

## “R2 objects are not displayed inline”

Check the object metadata written by the Worker:

- `contentType` must be `image/jpeg`, `image/png`, or `image/webp`;
- `contentDisposition` should be `inline`;
- `PUBLIC_IMAGE_ORIGIN` must match the public R2 origin without a trailing path;
- both Workers must point to the same bucket.

## “Wrangler types are stale”

Regenerate them after changing the Wrangler config:

```powershell
npm run worker:types
npm run worker:typecheck
```

Do not hand-edit generated platform types as a permanent fix.

## “A production token appeared in a screenshot”

Treat it as exposed, even if it is short-lived. Revoke the session, remove the screenshot from public history, and generate a new QR. Public documentation should use a safe demo screenshot, never a live production channel.

## “The QR appears but a scanner cannot read it”

Keep the QR at its rendered size, preserve the white quiet zone, do not crop the corners, and avoid recompressing it as a low-quality JPEG. The application renders a 248 px canvas with a white margin and medium error correction.
